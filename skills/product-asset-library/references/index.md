# 索引写入和查询

将本技能目录下的 scripts/library.py 交给 Python 3.9+ 执行。参数中的目录为用户给的素材根目录。输出数据库位于原有标记的“素材库整理结果”目录。服务用户时由 Codex 执行命令，用户只需要说自然语言。

- `library.py 目录 scan`：首次建文件索引；再运行时枚举以发现新文件、缺失文件，但只对元数据变化的文件算指纹。
- `library.py 目录 scan 图片/a.jpg 资料/产品表.csv`：只检查列出的相对路径，不遍历目录。已消失路径也可传入。移动文件同时提供新旧路径。查询已有关系直接用 find，跳过 scan。
- `library.py 目录 files`：返回本地索引中登记的路径、sha、是否存在、分类、描述与描述是否仍有效。
- `library.py 目录 ingest 临时输入.json`：原子更新列明的描述、用途和依据。把输入暂存在源目录以外。旧版迁移时复用素材总表中与当前 sha 匹配的人工描述；未确认用途保留在总表/待确认笔记。
- `library.py 目录 find --page contact --slot 封面`、`find --model P25`、`find --asset 图片/a.jpg`：可同时按站点、页面、型号、位置、素材或依据文件精确筛选。未知字段不参与筛选；用户只给中文名时可从用途列表或索引的说明解析键。
- `library.py 目录 export`：从数据库导出带筛选和原件链接的“用途索引.html”、Obsidian 用的“用途索引.md”。登记或撤销关系后刷新派生页面，并按变化更新受影响的产品卡、待确认项和上传清单。索引状态“已登记”表示有来源的用途；是否允许发布、是否已上传与实际附件编号分别判断。

JSON 示例（哈希值须从当前索引读取）：

```json
{"notes":[{"path":"图片/a.jpg","sha":"图片指纹","category":"海报屏","description":"展示正面和底座"}],"sources":[{"source":"产品表.csv","sha":"产品表指纹","uses":[{"pointer":"第 2 行","asset":"图片/a.jpg","sha":"图片指纹","site":"演示站","page":"products/p25","model":"P25","slot":"产品封面","evidence":"产品表第 2 行指定 a.jpg 为 P25 封面"}]}]}
```

每个 source 的 uses 是这一个来源当前的完整关系，可传空列表撤回旧关系。不同来源独立。用户在对话指定位置时，用固定 `@user/用途标识` 记录该决定及用户原话；修改相同指示时替换该组，保留其他用途。目标型号未知时留空；产品名称、产品页面标识、具体 SKU 分字段记录，避免将名称臆作型号。多个来源对同一单值位置说法冲突时输出待确认，保留各自的依据，以后续明确指示为准。数据库不写入 WordPress。扫描回报列出旧版本关联；来源换版时重读该来源并更新其关系集合，受影响的原件按需定位，其他来源不需要重读。
